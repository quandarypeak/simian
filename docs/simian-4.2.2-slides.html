Language spotlight · Go

Raw strings stop hiding duplicate logic

Two handlers built from the same template, differing only in a backtick raw string and a parameter name:

greetings.go
func GetUserGreeting(name string) string {
    greeting := `Hello there,
this is a welcome message` + name
    return strings.ToUpper(greeting)
}

By default Simian treats each raw string's contents as significant, and identifiers like name vs admin as distinct — so it sees two different functions. Turn on -ignoreStrings and -ignoreVariableNames and the structural duplication surfaces.

Language spotlight · TypeScript

Type annotations no longer break a match

Same arithmetic, different types on every line — including a tuple return type with a nested array element:

billing.ts
function calculateOrderTotal(price: number, quantity: number)
  : [number, string] {
    const tax: number = price * 0.08;
    const total: number = (price + tax) * quantity;

With -ignoreTypeAnnotations and -ignoreVariableNames, the tuple-type fix ([string[], number]-style nested arrays) lets Simian see through every type difference down to the shared arithmetic shape.

Language spotlight · Python

Triple-quotes and // stop lying to the parser

One query built with an f-string, the other with an rb-prefixed raw byte string — plus a pair of floor-division helpers:

queries.py
def fetch_user(uid: int) -> str:
    query = f"""
    SELECT * FROM users WHERE id = {uid}
    """

Before this branch, a triple-quoted string spanning lines could desync line numbers entirely. Now it's normalised first, the f/rb prefixes are stripped, and // is correctly read as floor-division — not a comment.

Fixed, not just new

Four classification bugs closed

Single-letter generics (T, K, V) were classed CONSTANT, not TYPE — and underscore-only names (_) were classed CONSTANT, not VARIABLE.

RecogniseIdentifiersTokenVisitor.java
if (Character.isLowerCase(name.charAt(i))) return false;
return true;
if (name.length() == 1) return false; // let it fall through to isTypeName
if (Character.isUpperCase(c)) hasUpperCase = true;
return hasUpperCase; // '_' has no uppercase → VARIABLE, not CONSTANT

Python's tokenizer read // as the start of a line comment, silently deleting everything after a floor-division on the same line.

PythonParser.java
tokenizer.slashSlashComments(false);
tokenizer.ordinaryChar('/'); // '//' is floor-division, not a comment

TypeScript's await was being stripped as a modifier — making awaited and non-awaited calls fingerprint identically.

TypeScriptParserFactory.java
// 'await' is intentionally absent from MODIFIERS — it's an
// expression operator, stripping it loses real behaviour.
